## Overview

RWD machines get a graphical login screen: users pick their name,
enter their password, choose any installed desktop session, and land
in a running session. It replaces starting RWD from a text console or
relying on another desktop's login manager, while reusing the proven
system login service underneath instead of re-auditing password
handling from scratch.

## Requirements

- [ ] **Pick a user and sign in**
  Users can select their account, enter their credentials, and land in
  a running graphical session.
- [ ] **Choose any installed session**
  Users can pick from all installed Wayland sessions, with RWD
  preselected as the default.
- [ ] **Prompt-driven authentication**
  The system renders whatever authentication prompts occur (password
  today, additional factors tomorrow) with no password-only flow baked
  in.
- [ ] **Failed login stays safe**
  Wrong credentials are rejected on the login screen with no
  distinction between bad user and bad secret, and never drop to a
  shell or console.
- [ ] **Dead session returns to login**
  A session that exits immediately after launch returns the user to
  the login screen with a plain-language notice instead of a black
  screen or a hung display.
- [ ] **Works from cold boot**
  The login screen appears without any existing desktop session
  running, straight from machine startup.

## Constraints

- The login daemon is adopted, not rebuilt: credential verification
  and session launch must go through the platform login service. The
  greeter never implements its own password checking.
- Same-UID and seat trust questions defer to the 004 production
  identity decision; the greeter makes no standalone security claim
  before that gate closes.
- The greeter must run with no desktop session present and must never
  depend on the RWD shell, compositor policy, or user-session services.
- Everything built here must be licensed GPL-3.0-or-later, matching
  the workspace and the adopted daemon's license.
- 1.0 must ship without graphical login; nothing in this spec gates
  1.0.

## Acceptance Criteria

- [ ] **Sign-in works**
  Entering valid credentials for a listed user starts the selected
  session; the login screen exits and the session's first window can
  receive input.
- [ ] **Session choice honored**
  Every installed Wayland session appears in the picker, RWD is
  preselected, and the launched process matches the session chosen.
- [ ] **Prompts render generically**
  A multi-prompt authentication exchange (e.g. password plus a second
  factor) displays each prompt in turn with no password-specific
  screen; all prompts are answerable from the greeter.
- [ ] **Bad credentials stay on screen**
  A wrong password redisplays the login screen with a single generic
  failure notice; no shell, console, or distinguishing error appears.
- [ ] **Crashed session recovers to login**
  Killing the launched session within 5 seconds of start returns to a
  usable login screen showing a plain-language notice.
- [ ] **Cold-boot login**
  From machine startup with no desktop session running, the login
  screen appears and a full sign-in succeeds.

## Technical Approach

- Pin and configure the adopted login daemon at a known release.
- Build the greeter UI as a native client on the RWD compositor stack,
  reusing the overlay and supervision patterns from the 001 slice.
- Drive the login conversation through the daemon's prompt protocol so
  new factors need no UI rework.
- Enumerate sessions from installed session files.
- Hand the verified session launch back to the daemon.

## Success Metrics

- Cold boot to usable login screen on every boot in test VMs, with no
  manual recovery step.
- Sign-in success rate for valid credentials in repeated runs, with
  zero drops to shell on bad credentials across fault-injection runs.
- Session-picker lists every installed session file with RWD default;
  launching each listed session at least once succeeds.

## Non-Goals

- Forking or patching the adopted daemon's internals.
- Seat and session tracking implementation (003) and production
  lock/auth identity design (004).
- Distro PAM stacks, SELinux policy, and packaging (006).
- Remote login, accessibility-certified greeter journeys beyond the
  keyboard baseline, and theming/styling systems — follow-on work.
