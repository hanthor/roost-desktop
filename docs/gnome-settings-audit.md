# GNOME 51 Settings and feature gap re-audit

Candidate: main `44edb6aca704ef0ada32b8c6111383ea5c3c6afe`, 2026-10-06. Reference: [GNOME control-center 51.0](https://github.com/GNOME/gnome-control-center/tree/6ae712c0454f2586f00821c3486150c1e8feb3e7), with panel C, Blueprint and GtkBuilder sources inspected. The [static item catalog](../tests/settings/gnome51-control-center-items.json) retains source locations; the [429-key desktop inventory](settings-desktop-inventory.md) is a separate input. Dynamic devices, apps, permissions and shortcuts require runtime enumeration. Neither inventory is a behavior pass.

Merged follow-ups through main `95490e3` add finite bounded Activities triggers (#369), GNOME enum reduced-motion handling (#370), truthful rejection of unsupported display mode/disable requests (#371), and strict native VM lifecycle qualification (#265). The source-pinned catalog remains the original audit input; those fixes do not close their broader capability or published-image acceptance issues.

Follow-up source review: main `c822ab91abbb8c07fdd89ddde5c81a71f7843ff3`, 2026-10-06. The original pinned catalog remains the audit input. Qualified merges add live calendar weekday/week-number preferences ([#381](https://github.com/tuna-os/tuna-desktop/pull/381)), logical output-aware LTR corners ([#386](https://github.com/tuna-os/tuna-desktop/pull/386)), and mouse/touchpad handedness with lock keyboard-state/focus repairs ([#379](https://github.com/tuna-os/tuna-desktop/pull/379)). These cover parts of the corresponding issues; their remaining requirements stay open.

**The desktop does not yet work fully with GNOME Settings.** Some controls work live, some only store preferences, some have no consumer, and service-backed controls lack shipped-image acceptance. Nested tests do not certify physical peripherals, multi-output GPU behavior or the final image.

Status: **live** means a source consumer exists (test scope is given in settings-map); **missing/partial** means a confirmed implementation limitation; **qualify** means an external service or runtime path requires evidence, not that the service is known absent.

[Central GitHub tracker](https://github.com/tuna-os/tuna-desktop/issues/367) contains all capability and existing production acceptance issues.

## GNOME application interoperability

The Settings catalog is not an application acceptance matrix. [#397](https://github.com/tuna-os/tuna-desktop/issues/397) tracks the 28 apps in the current official GNOME Core catalog; all remain awaiting complete per-app acceptance. Its scope includes principal operations, native/Flatpak launch, file/link handlers, portals and permissions, input/scaling, and lock/restart recovery. It does not replace the broader goal of GNOME app interoperability or cover every Circle/third-party app.

[#395](https://github.com/tuna-os/tuna-desktop/issues/395) tracks missing typed Mutter ServiceChannel provider paths for the GNOME file chooser and global-shortcuts provider. The current installed GNOME portal/type-1 path does not establish those additional roles. The native VM retains a GlobalShortcutsProvider access-denied warning; this is evidence of the missing provider contract, not proof that every Settings action or application fails. Provider identity and capture authorization must remain distinct when these paths are added.

## Existing production acceptance blockers

Lifecycle/suspend/VT/logout qualification remains in #62/#68; same-image performance and enforceable budgets in #73/#315; broader stress and final 24-hour soak in #203; test-strategy/security requirements in #8; physical hardware matrix in #314; release support commitments in #313. The strict native VM lane for merged PR #265 now passes lock repaint, stale successful PAM rejection after S3, fresh unlock, client repaint and painted greeter logout. Current native preview qualification is recorded above with its actual boot/lifecycle counts. The published-nightly lane for #273 previously failed final PAM unlock; the fresh signed package and image must still qualify the actual shipped payload. A negative owned presentation interval remains unresolved in [#434](https://github.com/tuna-os/tuna-desktop/issues/434); the full 24-hour soak has not completed. Coherent Arch image transactions and image-kernel receipts are pending in [#461](https://github.com/tuna-os/tuna-desktop/pull/461) / [#460](https://github.com/tuna-os/tuna-desktop/issues/460). Native preview evidence and passing initial logins do not establish final published-image acceptance.

The six existing switch-windows/cycle-windows/cycle-group bindings are corrected in the key inventory. Deprecated GTK, legacy screensaver and app-owned settings are tracked as ownership/compatibility decisions, not assumed GNOME 51 Settings regressions. GNOME Shell JavaScript extensions remain a separate compatibility difference; advertised Wayland globals do not imply complete behavior.

Acceptance should enumerate dynamic controls on the final shipped image, save per-control changed-behavior and negative-control results with exact source/package/image identities, and restore settings afterward. VM evidence covers virtual devices; GPU, radio, biometrics, touch/tablet and multiple physical monitors require separate evidence.
