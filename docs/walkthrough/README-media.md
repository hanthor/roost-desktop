# README media provenance

Captured on 2026-10-04 at 1280×800. These are actual rendered Roost frames and input-driven footage, not mockups. The overview demo uses three libadwaita fixture windows (Alpha, Beta, Gamma) from `scripts/lib/roost-test-window.py`.

The overview PNG, H.264 MP4 and animated GIF were captured in a private D-Bus session and Xvfb display using the GTK compositor/shell binaries from [PR #240](https://github.com/hanthor/roost-desktop/pull/240), [CI run 37175952333](https://github.com/hanthor/roost-desktop/actions/runs/37175952333), checkout `49a70b0` (PR source `ad87517` merged with workspace-insertion source `bd18c76`). This candidate includes the workspace-insertion work in PR #234. Input opens the overview with Super, selects Beta's live preview, opens the overview again and dismisses it with Escape. Compositor state checks confirm three mapped windows, three overview previews and Beta focus after selection. The video runs for 12 seconds at 15 fps; the GIF is a smaller 640×400, 8 fps derivative. Neither speed establishes a performance benchmark.

The quick-settings and app-grid PNGs come from the successful GTK proof in [CI run 37173873772](https://github.com/hanthor/roost-desktop/actions/runs/37173873772), source revision `92987f2`. The service controls and catalog in this proof use fixtures on isolated buses. This run's GTK journey passed; its separate Marlin VM portal gate failed and is not asserted by these screenshots.

To reproduce the UI, run `scripts/roost-gtk-shell-proof` on a development machine and retain `05-overview.png`, `03-quick-settings.png` and `11-app-grid.png`. For video, record the isolated Xvfb display with ffmpeg's x11grab while driving Super and preview selection through xdotool. Keep the complete frame at 1280×800, encode H.264 with yuv420p and faststart for the MP4, and retain the original capture before deriving the GIF.
